## 2. The device-loss bug: what is established

Symptom: mid-game `Lost VkDevice ... (code 9): Invalid Resource`, sometimes code 3 (GPU address fault) or code 2 (GPU hang). Engine then hangs until the watchdog kills it.

Reproduction:
- Live lobby games on **Supreme Isthmus v2.1** with the spectator harness (`specjoin.py --mappref "Supreme Isthmus"` + `SPEC_HOVER=1`): base config dies in 84–441 s, 8 of 8 runs. All That Glitters: clean 3 of 3.
- Replays: clean in every variant (smooth camera, camera teleports, sim bunching, `/skip` catch-up, self-hosted bot game) **except** a replay that takes a full-frame screenshot every 5 s: `replaysoak.py --demo jobs/tmp/isthmus.sdfz --skipto 6000 --hover --hoverloop --shotat "$(cat jobs/tmp/shots5.txt)"` → GPU hang at 538 s (run `rr-shots5`). A screenshot is `glReadPixels` → 26.5 MB staging buffer → wait → destroy.

Fix that works: **MoltenVK with retained command buffer references**. Branch `fix/retain-references` in `~/Code/moltenvk-src` (commit c06a7e3a, on top of `fix/query-pool-lifetime` f864d796): in `MVKQueueCommandBufferSubmission::getActiveMTLCommandBuffer` set `needsRetain = true` whenever there is no residency set. Result: Supreme Isthmus live 3 of 3 clean for 10 min (runs retain1–3), fps on a replay identical to stock (55/55 vs 55/58). Built as `/private/tmp/mvk-ship.dylib`. A live soak of it (`shipsoak.sh`: ship1, ship2 on Isthmus, ship3 any map) was running when the session ended: result in `jobs/tmp/shipsoak.log`.

Why it works (mechanism, partly proven): without retained references Metal reads a resource that was already released. Something releases resources before the GPU is done with them. zink's own accounting never destroys a resource with pending usage (probe in `zink_destroy_resource_object` fired 0 times before a loss), Vulkan validation (core and sync) reports nothing, so zink and the layer both *believe* the work completed. Leading explanation: zink signals its batch timeline semaphore from a **separate, empty VkSubmitInfo**; MoltenVK turns that into its own empty MTLCommandBuffer with `encodeSignalEvent`, which can complete before the previous MTLCommandBuffer's GPU work. Not proven: a zink patch that merges the signal into the work submit (`patches/mesa-signal-test/0009`) still died 2/2, but that patch was never verified to take effect. The standalone Vulkan reproducer for the ordering (heavy dispatch + marker in submit A, timeline signal in empty submit B, host waits on timeline then reads the marker) was designed but not written: put it in `/private/tmp/sigorder/`, compile like `/private/tmp/mvkrepro/repro.c` (`clang -I/opt/homebrew/include -L/opt/homebrew/opt/vulkan-loader/lib -lvulkan`, `VK_ICD_FILENAMES` → an icd json pointing at the dylib under test).

Refuted this session (each by live runs on Isthmus unless noted): `MVK_CONFIG_USE_MTLHEAP=0`, purgeable memory removed (nopurge 2/2 died), `GALLIUM_THREAD=0` (delays only: 3 clean then died at 581 s), zink no-inferred-unsync maps (3/3 died), zink texture-subdata on driver thread (1 clean, weak), `ZINK_DEBUG=sync` (died faster), `MVK_CONFIG_RESUME_LOST_DEVICE=1` (survives code 9/3 but not a following GPU hang), `MTL_DEBUG_LAYER=1` (no encode-time errors), Vulkan validation core+sync (0 messages), KosmicKrisp instead of MoltenVK (clean 10 min once, 28 fps).

Other facts: the driver does not grant GL reset notification (`GL reset notification: none` in every log), so `glGetGraphicsResetStatus` is useless; the engine now detects a dead GPU via its own present fence (5 s without a completed frame → quit), commit 16086b59a2, not yet seen firing in a real loss (the driver thread blocks inside MoltenVK's 64-command-buffer semaphore, so it may not reach the check). Killed engines leave 0-byte demos.

## 6. Harness cheat sheet

`replaysoak.py` flags used: `--demo`, `--dylib`, `--argbuffers 0`, `--minutes`, `--speed`, `--skipto N` (`--skipmode skip` for `/skip` catch-up), `--hover --hoverloop` (cursor sweep, screenshots at each stop), `--shotat f1,f2,...`, `--override <widget or Shaders/ file>`, `--env K=V`, `--cfg "Key=Val;..."`, `--loadwait N`, `--nocamera`, `--fantest`, `--compareat N`, `--port`. Needs `SPEC_APP` (bundle to run). Verdicts: `clean`, `demo-end`, `DEVICE-LOSS`, `stuck-loading`, `sim-stalled`.

`specjoin.py` flags: `--tag`, `--dylib`, `--minutes`, `--userlua`, `--mvkdebug`, `--minage/--maxage` (game age in minutes), `--mappref "Supreme Isthmus"`, `--attempts`, `--pooling`. `SPEC_HOVER=1` adds the top-bar cursor sweep. Verdict line carries `resumed=N`. Kills the engine 10 s after a loss.

Demos: `jobs/tmp/isthmus.sdfz` (full 26-player Supreme Isthmus game, 3.1 MB), `jobs/tmp/deadgame.sdfz` (4.6 MB, another Isthmus game), `jobs/tmp/issue4.sdfz` (Baryon Tar Lake, chat glitch at 8:37). Many Isthmus demos in the user's demos dir are 0 bytes (broken).

Pitfalls learned: gui_chat.lua is at Lua's 200-local limit (new top-level `local` = widget silently fails to load); BAR's emmylua CI counts rippled and line-shifted findings as new; validation-layer manifests need an absolute `library_path` (jobs/tmp/vklayer); the loader keeps 64 MTLCommandBuffers in flight; `sleep` chains are blocked in the assistant shell, use until-loops; `log` is a zsh builtin, use `/usr/bin/log`.
